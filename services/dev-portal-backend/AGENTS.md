# dev-portal-backend

## Purpose

The backend of the [developer portal](../../developer-portal/AGENTS.md), reached
through its `/api/dev/` proxy. It keeps scenarios (`scenarios/`, baked in, plus
user-saved ones in `/var/scenarios`) and the run history (`/var/history.jsonl`,
posted by `consent-portal-backend` and `dienstverlener-backend` through
`DEV_PORTAL_BACKEND_URL`). It reads what the chain recorded for a run (PDP
decisions, FSC transaction logs, LDV chains), takes the collector's OTLP spans
for the live strip and watch-next, and relays the ASI tab to the reference QTSP.
It does not proxy chain calls, so traces get no extra hop. A block whose
configuration is missing answers empty or with its own error; the service still
starts. The flat `package main` is not an exception to
[../AGENTS.md](../AGENTS.md): a block that changes moves behind a port, as
`internal/testpid` and `internal/revocation` did.

## Contracts

- `/decisions` and `/fsc/txlog/` key on the `Fsc-Transaction-Id`, `/ldv/` on the
  trace id (normalised to lowercase hex); one value when a request crosses FSC
  once.
- `/decisions` returns `audit` (the ADL, the record of a decision) and `engine`
  (Loki's console decision log, observability only), each with its own error;
  `part=` fetches one. Behind the Inway the ADL lacks `adl.fsc.transaction_id`,
  so `adlDecisionsQuery` falls back to the header in the stored request
  ([#369](https://github.com/ICTU/GBO-demo/issues/369)).
- `rules.json` is generated by `scripts/gen-rules-json.sh`; CI fails when it is
  stale. The image bakes in `rules.json` and `policies/` (build context is the
  repository root); Compose bind-mounts both for live edits.
- Watch-next fires only on spans matching `entryPointRules`: a new flow entry
  needs a rule there. Session and usecase filters reject only a trace that
  contradicts them; an untagged trace wakes every watcher.
- Predefined issuance scenarios get `dienstverlener_oin` injected
  (`consumerPeerIDFor`): `IR_CONSUMER_PEER_ID` for `lvg:` scopes, else
  `DVTP_CONSUMER_PEER_ID`. The PDP compares it with the FSC caller. User-saved
  scenarios are left as entered.
- `LDV_LOGBOOKS` ids must equal what records hold in `dpl.read.nextLogbookId`; a
  new logbook in Compose needs an entry here.
- A txlog peer needs its prefix in `loadConfig`, plus env and a certificate
  mount in `docker-compose.yml`. `BD_HV`, `BD_EDI` and `BD_ASIP` read a remote
  provider's peer-facing Manager from a consumer peer's view (no `group_id`),
  for the simulation deployment; Compose reads BD's own txlog-api (`BD`) and
  sets none of them.
- Test PID (`TEST_PID_OFFERS_URL`) and revocation
  (`CREDENTIAL_ISSUER_INTERNAL_URL`) are demo shortcuts: anyone reaching the
  backend gets a PID or revokes anything. Never on in a shared environment.

## Pitfalls

- Promtail splices timestamps into console lines over 16 KiB, so denials showed
  no engine detail; `repairDockerSplits` undoes it:
  [#373](https://github.com/ICTU/GBO-demo/pull/373).
- Services emit the stable OTel HTTP attributes; watch-next never fired until
  `firstAttr` read both: [#434](https://github.com/ICTU/GBO-demo/pull/434).
- `http.DefaultClient` has no timeout and hung handlers; use `upstreamClient`:
  [#153](https://github.com/ICTU/GBO-demo/pull/153).
- A hard-coded consumer Peer ID made valid simulation queries fail:
  [#277](https://github.com/ICTU/GBO-demo/pull/277).

## Verify

`go test -race ./...`; after a policy change, `scripts/gen-rules-json.sh`. End
to end, after a run:
`curl -s "http://localhost:9407/decisions?transaction_id=<id>" | jq`, and
likewise `/fsc/txlog/<id>` and `/ldv/<trace-id>`.

## Decisions

- ADL as the audit source, Loki beside it, no explain or replay:
  [#373](https://github.com/ICTU/GBO-demo/pull/373).
- The LDV chain is followed through `nextLogbookId` from start logbooks:
  [#366](https://github.com/ICTU/GBO-demo/pull/366).
- Watch-next and history bound to a demo session cookie:
  [#207](https://github.com/ICTU/GBO-demo/pull/207).
- Revocation off by default: [#698](https://github.com/ICTU/GBO-demo/pull/698).
